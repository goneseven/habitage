# Habitage — Development Master Brief

## Role

Act as a senior TypeScript engineer, software architect and product designer.

Build Habitage, a premium personal home inventory and asset intelligence application.

The application provides a structured digital archive of household possessions, including their locations, photographs, purchase records, documents, warranties, maintenance history and financial valuations.

## Product principles

- Premium consumer-grade user experience.
- Strong TypeScript architecture.
- Modular, reusable components.
- Local-first data persistence.
- Responsive desktop, tablet and mobile layouts.
- Meaningful functionality rather than decorative mockups.
- Accessible interactions and consistent design patterns.
- No mandatory cloud services or external API dependencies.

## Visual direction

Use a sophisticated tropical-inspired colour palette:

- Deep forest green.
- Jade and botanical green.
- Warm ivory and linen.
- Muted brass and gold.
- Soft neutral backgrounds.

Use elegant editorial typography, beautiful photography, refined spacing, subtle gradients, restrained animations and exceptional visual hierarchy.

Avoid generic SaaS dashboard templates.

## Mandatory project workflow

### Initial preparation

1. Inspect the existing codebase before modifying anything.
2. Identify existing frameworks, dependencies, architecture and conventions.
3. Create a comprehensive PLAN.md.
4. Document the product vision, architecture, domain models, development phases, dependencies, implementation decisions and completion criteria.
5. Create README.md with project introduction, installation, build, run and test instructions.
6. Create an appropriate .gitignore file.
7. Establish a clean initial project structure.

### Feature-by-feature implementation

Follow PLAN.md as the single source of truth.

Implement exactly one feature at a time.

For each feature:

1. Understand its dependencies and completion criteria.
2. Implement its complete UI.
3. Implement its business logic.
4. Integrate persistence and related components.
5. Handle edge cases and invalid input.
6. Manually verify its functionality.
7. Update PLAN.md with implementation details and completion status.
8. Commit the completed feature to Git.
9. Maintain .gitignore file
10. Summarise what was implemented.
11. Identify the next incomplete feature.
12. Stop and wait for explicit permission.

Do not start the next feature automatically.

When instructed to "Continue", resume from the next incomplete feature without repeating previous work.

Do not ask questions or request approval while implementing the current feature. Make sensible engineering and product decisions independently.

If a feature is too large, divide it into smaller independently verifiable sub-features and request approval between them.

### Quality requirements

- No unfinished features.
- No decorative controls without functionality.
- No fake persistence.
- No placeholder buttons.
- No unexplained financial calculations.
- No duplicated business logic.
- No unsafe assumptions about imported data.
- Maintain strict TypeScript typing.
- Handle loading, empty, success and error states.
- Ensure responsive behaviour.
- Preserve existing user data during application updates.

### Initial execution instruction

Start by inspecting the existing codebase.

Create PLAN.md and README.md, establish .gitignore and the application structure, then immediately implement the first feature specified in PLAN.md.

Complete and manually verify that feature.

Update the plan, commit the implementation, provide a concise completion summary and identify the next feature.

Stop and wait for my explicit instruction to continue.
